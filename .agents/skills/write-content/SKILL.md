# 워크북 컨텐츠 작성 스킬

이 프로젝트에는 두 가지 컨텐츠 디렉터리가 있다. 글을 작성하기 전에 반드시 어떤 타입인지 분류한다.

## 컨텐츠 타입 분류

### 타입 1 — `skills/` (스킬 & 플러그인 카드)

**경로:** `skills/<slug>.mdx`
**용도:** Codex 스킬 또는 플러그인을 소개하는 카드형 항목

카테고리:
- `skill` — Codex `.Codex/skills/`에 설치하는 개인/프로젝트 스킬
- `plugin` — `/plugin install`로 설치하는 플러그인 패키지

**필수 frontmatter:**
```yaml
---
title: "전체 제목 (상세 페이지 h1)"
name: "카드에 표시되는 짧은 이름"
description: "카드와 상세 페이지에 쓰이는 한 줄 설명"
category: skill  # 또는 plugin
date: YYYY-MM-DD
---
```

**선택 frontmatter:**
```yaml
github: "https://github.com/..."   # GitHub 버튼 표시
installCmd: "/plugin install ..."   # 설치 명령어 표시
```

**본문 구조 (plugin):**
1. 한 문단 요약
2. `## 왜 필요한가` — 해결하는 문제
3. `## 설치 방법` — 환경별 설치 명령
4. `## 설치하면 무엇이 달라지나` — 적용 전후 비교, 워크플로 흐름
5. `## 주요 기능 / 스킬 구조` — 표 또는 목록
6. `## 언제 쓰면 좋은가` — 적합/부적합 상황
7. `## 주의할 점` — 제약, 비용, 호환성
8. `## 한 문장으로 정리` — 핵심 한 줄
9. `## 참고 링크`

**본문 구조 (skill):**
1. `## 개요` — 스킬이 하는 일
2. `## 워크플로우 단계` — 번호 목록 또는 코드 블록
3. `## 사용법` — 트리거 방법 (`/skill-name` 등)
4. `## 옵션 / 규칙` — 적용 규칙이나 파라미터
5. `## 예시` — 실제 사용 예

### 타입 2 — `content/` (블로그 포스트)

**경로:** `content/<slug>.mdx`
**용도:** Codex 기능, 개념, 사용법을 설명하는 교육용 아티클

**필수 frontmatter:**
```yaml
---
title: 포스트 제목
description: 한 줄 설명
date: YYYY-MM-DD
order: 숫자  # 목록 정렬 순서. 기존 가장 높은 order + 1
category: Codex
---
```

**본문 구조:**
- `## ` 섹션 제목 (이모지 선택 사항)
- 표, 코드 블록, 인용 적극 활용
- 각 섹션은 `---` 수평선으로 구분

## 분류 절차

사용자 요청을 받으면:

1. **타입 판단** — 아래 기준으로 결정한다:
   - 특정 스킬/플러그인을 소개하는 글 → `skills/` (skill 또는 plugin)
   - Codex 기능/개념/팁을 설명하는 글 → `content/`
   - 애매하면 사용자에게 한 가지 질문으로 확인한다

2. **slug 결정** — 영문 소문자, 하이픈 구분, 기존 파일명과 충돌 없는지 확인

3. **필요 정보 수집** — 타입별 필수 frontmatter 값이 없으면 질문한다
   - plugin/skill: `github` URL, `installCmd` 여부
   - post: 적절한 `order` 값 (기존 `content/` 파일들의 최대값 + 1)

4. **파일 작성** — 해당 디렉터리에 MDX 파일을 생성한다

5. **확인** — 작성 후 파일 경로와 frontmatter를 사용자에게 보고한다

## 미래 타입 확장

새로운 카테고리가 추가될 경우, 이 스킬 파일을 업데이트해 타입 3, 타입 4를 추가한다. 현재 없는 타입 요청이 들어오면 사용자와 협의해 구조를 먼저 정의한다.
