Taste Skill은 AI가 만드는 웹 인터페이스의 레이아웃, 타이포그래피, 모션, 여백을 다듬어 평범한 boilerplate UI를 피하게 하는 프론트엔드 디자인용 Agent Skill 모음입니다. 저장소의 본체는 `skills/` 아래 여러 `SKILL.md`로 구성된 portable skill 컬렉션이며, Claude Code용 `.claude-plugin` manifest도 함께 제공해 플러그인 packaging을 병행합니다.

## 왜 필요한가

AI는 UI 코드를 빠르게 만들지만, 시각적 판단은 균질하고 안전한 기본 패턴 — 반복되는 카드, 보라색 gradient, 균일한 간격 — 으로 수렴하기 쉽습니다. Taste Skill은 디자인 취향을 하나의 거대한 프롬프트로 강제하는 대신, greenfield·redesign·GPT/Codex·image-first·스타일 방향별로 작은 스킬로 나눠 제공합니다.

## 설치 방법

### 공통: skills CLI

전체 스킬 설치:

```bash
npx skills add https://github.com/Leonxlnx/taste-skill
```

특정 스킬 하나만 설치할 때는 폴더명이 아니라 각 `SKILL.md` frontmatter의 `name:` 값, 즉 install name을 사용합니다.

```bash
npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"
```

기본 `taste-skill`은 현재 experimental v2이며 install name은 `design-taste-frontend`입니다. 기존 v1의 정확한 동작을 유지해야 한다면 `design-taste-frontend-v1`을 명시해 설치합니다.

### Codex

이 저장소는 Codex plugin manifest를 제공하지 않습니다. README가 안내하는 Codex 경로는 `npx skills add`로 portable skill을 설치하거나, 필요한 `SKILL.md`를 프로젝트에 복사하거나, `SKILL.md`를 Codex 대화에 붙여 넣는 방식입니다. Codex용으로는 기본 스킬보다 더 엄격한 variant인 `gpt-taste`가 있습니다. Codex image mode나 ChatGPT Images에서는 image-generation skill로 reference frame을 먼저 생성한 뒤, 그 이미지를 Codex 구현 작업에 넘길 수 있습니다.

### Claude Code

Claude Code에서도 `npx skills add`로 같은 portable skill을 설치할 수 있고, `.claude-plugin` 아래 plugin manifest와 marketplace metadata도 제공됩니다. 다만 README가 명시적으로 안내하는 기본 설치 명령은 `npx skills add`뿐이므로, 특정 `/plugin marketplace add` 또는 `/plugin install` 명령이 필요하다면 설치 시점의 Claude Code marketplace 안내를 별도로 확인하는 것이 안전합니다.

## 스킬 구성

README는 구현 스킬과 이미지 생성 스킬을 구분합니다. 구현 스킬은 코드를 출력하고, 이미지 생성 스킬은 코드 대신 design reference 이미지를 만듭니다.

| 폴더 | Install name | 용도 |
| --- | --- | --- |
| `taste-skill` | `design-taste-frontend` | 기본 v2. brief에서 디자인 언어를 추론하고 variance·motion·density를 조정한다. |
| `taste-skill-v1` | `design-taste-frontend-v1` | 기존 v1의 동작을 유지해야 할 때 사용한다. |
| `gpt-tasteskill` | `gpt-taste` | GPT/Codex용으로 더 강한 anti-slop, layout, GSAP 규칙을 적용한다. |
| `image-to-code-skill` | `image-to-code` | reference 이미지를 생성·분석한 뒤 코드로 구현하는 흐름이다. |
| `redesign-skill` | `redesign-existing-projects` | 기존 프로젝트 UI를 audit한 뒤 계층·간격·스타일을 개선한다. |
| `soft-skill` | `high-end-visual-design` | 여백, 부드러운 대비, 고급 폰트와 spring motion을 활용한 차분한 UI다. |
| `output-skill` | `full-output-enforcement` | 에이전트가 미완성 코드나 placeholder로 끝내는 문제를 줄인다. |
| `minimalist-skill` | `minimalist-ui` | 절제된 색과 선명한 구조의 editorial product UI 방향이다. |
| `brutalist-skill` | `industrial-brutalist-ui` | Swiss typography, 강한 대비, 실험적인 레이아웃을 사용한다. |
| `stitch-skill` | `stitch-design-taste` | Google Stitch 호환 규칙과 선택적 `DESIGN.md` export 형식을 제공한다. |
| `imagegen-frontend-web` | `imagegen-frontend-web` | 웹사이트 comp와 landing page reference를 만든다. |
| `imagegen-frontend-mobile` | `imagegen-frontend-mobile` | 모바일 화면, 흐름, mockup 세트를 만든다. |
| `brandkit` | `brandkit` | 로고 방향, 팔레트, type, identity application을 담은 brand board를 만든다. |

## 기본 스킬의 조절값

`design-taste-frontend`는 상단에 1~10 범위의 숫자 설정 세 가지를 둡니다.

- `DESIGN_VARIANCE`: 낮으면 가운데 정렬·정돈된 배치, 높으면 비대칭·현대적인 layout 실험을 늘린다.
- `MOTION_INTENSITY`: 낮으면 hover 중심, 높으면 scroll·magnetic 등 깊은 animation을 사용한다.
- `VISUAL_DENSITY`: 낮으면 여백이 넓고, 높으면 한 viewport에 더 많은 정보를 넣는다.

## 언제 쓰면 좋은가

- 에이전트가 만든 화면이 반복적인 카드, 보라색 gradient, 균일한 간격처럼 "AI 기본값"으로 보일 때
- 새 프론트엔드에서 디자인 언어를 먼저 정하고 구현하고 싶을 때
- 기존 제품의 정보 계층·spacing·typography를 redesign하고 싶을 때
- 먼저 reference image를 만들고, 그 결과를 코드 구현의 visual target으로 쓰고 싶을 때

## 주의할 점

기본 `design-taste-frontend` v2는 experimental입니다. 안정성이 우선이거나 기존 출력 특성에 의존한다면 v1을 명시적으로 선택해야 합니다. 스타일 스킬을 여러 개 동시에 적용하면 서로 다른 visual language가 충돌할 수 있고, 각 스킬은 한 가지 방향만 맡으므로 한꺼번에 모두 쓸 필요는 없습니다. image-generation skill은 구현 코드를 내지 않으므로, 생성한 frame을 Codex·Cursor·Claude Code에 넘기는 후속 구현 단계가 필요합니다. React, Vue, Svelte 같은 특정 프레임워크 API가 아니라 디자인 의도를 대상으로 하므로, 프레임워크별 코드 품질이나 접근성 검증을 대신하지 않습니다.

## 한 문장으로 정리

Taste Skill은 AI UI의 시각적 판단을 하나의 거대한 프롬프트가 아니라, 상황별로 고를 수 있는 13개의 작은 디자인 취향 스킬로 나눠 제공하는 라이브러리입니다.
