# improve-token-efficiency: Claude Code 세션 로그로 토큰 비용과 낭비 패턴을 보는 스킬

`improve-token-efficiency`는 Claude Code가 남긴 JSONL 세션 로그를 분석해 레포 단위 토큰 사용량, 캐시 효율, 비용, 효율 점수, 절감안을 보여주는 스킬입니다. "이번 달 얼마 썼지?"에서 끝나지 않고, 왜 비용이 늘었는지와 어디부터 줄이면 좋은지를 함께 보여줍니다.

Claude Code 세션 로그에는 assistant 메시지의 usage 정보가 남습니다. 이 안에는 input tokens, output tokens, cache creation, cache read 같은 값이 들어 있으므로, 별도 API 호출 없이도 세션별 비용 구조를 꽤 구체적으로 재구성할 수 있습니다.

## 왜 필요한가

AI 코딩 비용은 대개 한 번에 폭발하지 않습니다. 긴 세션이 조금씩 누적되고, 같은 파일을 여러 번 읽고, 캐시를 잘 못 쓰고, 고비용 모델을 모든 작업에 쓰면서 조용히 커집니다. 문제는 이런 낭비가 대화 화면만 봐서는 잘 보이지 않는다는 점입니다.

`improve-token-efficiency`는 이 흐름을 숫자로 바꿉니다. 어떤 세션이 전체 비용의 대부분을 차지했는지, 캐시 적중률이 낮은지, 중복 Read가 많은지, tool call이 산출 대비 과한지를 대시보드로 보여줍니다.

## 분석 흐름

먼저 대상 레포를 정합니다. 사용자가 경로를 주면 그 경로를 쓰고, 없으면 현재 작업 디렉터리를 기준으로 합니다. 스크립트는 레포 경로를 Claude Code의 `~/.claude/projects/...` 프로젝트 키로 변환해 JSONL 세션 로그를 찾습니다.

그 다음 `scripts/analyze_sessions.py`가 세션 로그를 파싱합니다. usage가 없는 빈 세션은 제외하고, 세션별 input, output, cache write, cache read, tool call, 중복 read, 비용, 점수를 계산합니다.

마지막으로 `scripts/build_dashboard.py`가 분석 JSON을 단일 HTML 리포트로 바꿉니다. 대시보드에는 KPI 카드, 비용 내역, Pareto 차트, 등급 히스토그램, cost vs score 산점도, rubric 표, top sessions 표, 개선 카드가 들어갑니다.

## 효율 점수

스킬은 네 가지 기준으로 세션 효율을 점수화합니다.

| 지표 | 가중치 | 보는 것 |
| --- | ---: | --- |
| Cache utilization | 40% | 전체 입력 대비 cache read 비율 |
| Output density | 20% | 입력 대비 산출 비율 |
| Read redundancy | 20% | 같은 파일을 반복해서 읽은 비율 |
| Tool economy | 20% | 출력 1k 토큰당 tool call 수 |

이 조합이 꽤 현실적입니다. 캐시 적중률이 낮으면 매 turn 같은 컨텍스트를 다시 보내는 셈이고, 중복 read가 높으면 탐색 전에 범위를 좁히지 못했다는 뜻입니다. tool call이 너무 많으면 일은 하고 있지만 방향을 못 잡은 세션일 수 있습니다.

## 대시보드에서 보는 것

가장 먼저 누적 비용, 총 토큰, 캐시 적중률, 평균 점수, tool call 수를 봅니다. 그 다음 Pareto 차트로 상위 몇 개 세션이 비용을 얼마나 차지하는지 확인합니다. 대개 비용 최적화는 평균 세션보다 상위 비용 세션을 먼저 보는 쪽이 빠릅니다.

Cost vs Score 산점도도 중요합니다. 비싸고 점수가 낮은 세션은 구조적 낭비 가능성이 높습니다. 반대로 비싸지만 점수가 높은 세션은 실제로 큰 작업을 한 것일 수 있으니, 단순히 비용만 보고 줄이면 안 됩니다.

## 절감안

스킬은 여섯 가지 개선안을 계산합니다.

- Opus 작업 일부를 Sonnet으로 라우팅
- 장시간 세션에서 `/compact` 사용
- 이미지 포함 세션 관리
- Cache TTL 1h를 5m로 낮출 수 있는 부분 찾기
- 세션 scope 축소
- 중복 Read 제거

이 절감액은 휴리스틱입니다. 그래서 "정답"이라기보다 실험 우선순위로 읽는 게 좋습니다. 개선안을 적용한 뒤 같은 분석을 다시 돌려 실제 절감이 있었는지 재측정해야 합니다.

## 언제 쓰면 좋은가

Claude Code를 많이 쓰는 레포, 팀 단위로 AI 비용을 보고 싶은 레포, 고비용 세션이 자주 생기는 프로젝트에 특히 좋습니다. "모델을 낮추자" 같은 단순 처방 전에 실제 낭비가 캐시, 세션 길이, 이미지, 읽기 패턴, 도구 사용 중 어디서 생기는지 분리할 수 있습니다.

또 개인에게도 쓸모가 큽니다. 세션 습관을 보면 내가 같은 파일을 자주 다시 읽는지, 탐색을 너무 넓게 시작하는지, `/compact` 타이밍을 놓치는지 바로 드러납니다.

## 주의할 점

세션 디렉터리가 없으면 분석할 데이터도 없습니다. 모든 세션에 usage 기록이 없다면 오래된 CLI 버전에서 만든 로그일 수 있습니다. 새 모델이 추가되면 스크립트의 가격표가 최신인지 확인해야 합니다.

HTML 리포트는 기본적으로 Chart.js CDN을 사용합니다. 오프라인 환경에서는 로컬 Chart.js를 인라인으로 넣는 옵션을 써야 합니다.

## 한 문장으로 정리

`improve-token-efficiency`는 Claude Code 사용 비용을 감으로 줄이는 대신, 실제 세션 로그에서 캐시, 읽기, 모델, 세션 길이 문제를 찾아 절감 우선순위로 바꿔주는 스킬입니다.
