`hookify`는 Claude Code에서 반복적으로 발생하는 원치 않는 행동을 hook 규칙으로 바꿔주는 공식 플러그인입니다. "이 명령은 쓰기 전에 경고해줘", "이런 파일에는 이 패턴을 넣지 마", "테스트 없이 끝내지 마" 같은 지시를 프로젝트 로컬 rule 파일로 만들고, 다음 tool use부터 바로 적용합니다.

핵심은 복잡한 `hooks.json`을 직접 편집하지 않아도 된다는 점입니다. `hookify`는 간단한 Markdown 파일과 YAML frontmatter로 규칙을 정의합니다. 사용자는 행동을 설명하고, Claude는 event, pattern, action을 정리해 `.claude/hookify.*.local.md` 파일을 만듭니다.

## 왜 필요한가

AI 코딩 에이전트는 같은 실수를 반복할 수 있습니다.

- 위험한 shell command를 너무 쉽게 제안합니다.
- debug statement를 남깁니다.
- 민감한 파일이나 secret 패턴을 건드립니다.
- 프로젝트 규칙과 맞지 않는 파일 수정을 반복합니다.
- 검증 없이 작업을 마무리하려 합니다.

이런 문제를 매번 대화로 다시 말하는 대신, `hookify`는 guardrail을 프로젝트에 남깁니다. 경고만 할 수도 있고, 위험한 행동은 아예 차단할 수도 있습니다.

## 설치 방법

Claude Code에서는 Anthropic 공식 플러그인 marketplace에서 설치할 수 있습니다.

```text
/plugin install hookify@claude-plugins-official
```

공식 marketplace가 등록되어 있지 않다면 먼저 추가합니다.

```text
/plugin marketplace add anthropics/claude-plugins-official
```

## 설치하면 무엇이 달라지나

1. `/hookify`로 새 hook 규칙을 만들 수 있습니다.
2. 명시 지시를 규칙으로 바꿀 수 있습니다.
3. 인자 없이 실행하면 최근 대화에서 correction이나 frustration을 분석해 규칙 후보를 찾습니다.
4. rule은 `.claude/hookify.{name}.local.md` 파일로 저장됩니다.
5. `bash`, `file`, `stop`, `prompt`, `all` event를 감시할 수 있습니다.
6. `warn` 또는 `block` action을 선택할 수 있습니다.
7. 규칙은 restart 없이 다음 tool use부터 적용됩니다.

## 주요 기능 / 스킬 구조

| 구분 | 구성 요소 | 역할 |
| --- | --- | --- |
| 명령 | `commands/hookify.md` | 대화 분석, 사용자 확인, rule 파일 생성 흐름을 정의합니다. |
| 보조 명령 | `commands/` | `/hookify:list`, `/hookify:configure`, `/hookify:help` 같은 관리 명령을 제공합니다. |
| 스킬 | `skills/writing-rules` | hookify rule 파일 형식과 syntax를 작성할 때 참조합니다. |
| 에이전트 | `agents/` | 최근 대화에서 원치 않는 행동 패턴을 찾는 데 사용됩니다. |
| 실행 로직 | `core/`, `hooks/`, `matchers/`, `utils/` | rule loading, event matching, hook 실행을 담당합니다. |
| 예시 | `examples/` | 자주 쓰는 rule 예시를 제공합니다. |

## Rule 파일 형식

규칙은 프로젝트 루트의 `.claude/` 폴더에 Markdown 파일로 둡니다.

```markdown
---
name: block-dangerous-rm
enabled: true
event: bash
pattern: rm\s+-rf
action: block
---

Dangerous rm command detected. Verify the path and use a safer approach.
```

여러 조건을 함께 사용할 수도 있습니다.

```markdown
---
name: warn-sensitive-files
enabled: true
event: file
action: warn
conditions:
  - field: file_path
    operator: regex_match
    pattern: \.env$|credentials|secrets
  - field: new_text
    operator: contains
    pattern: KEY
---

Sensitive file edit detected. Ensure credentials are not hardcoded.
```

## 기본 워크플로

명시적인 행동이 있으면 `/hookify Warn me when I use rm -rf commands`처럼 실행합니다. 최근 대화에서 반복된 문제를 찾고 싶다면 `/hookify`만 실행합니다. Claude가 최근 대화에서 "하지 말라"는 지시, correction, 불만 신호를 찾고 규칙 후보를 제안합니다.

그다음 어떤 행동을 hookify할지, warn인지 block인지, 어떤 pattern으로 감지할지 확인합니다. 확인이 끝나면 `.claude/hookify.{rule-name}.local.md` 파일을 현재 프로젝트의 `.claude/` 폴더에 생성합니다.

파일이 생성되면 바로 적용됩니다. restart가 필요 없습니다. `/hookify:list`로 규칙을 확인하고, `/hookify:configure`로 enable/disable을 조정할 수 있습니다.

## 언제 쓰면 좋은가

- 위험한 shell command를 막거나 경고하고 싶을 때
- debug code, hardcoded secret, 특정 파일 수정 패턴을 감지하고 싶을 때
- 테스트 실행 없이 작업을 끝내지 못하게 하고 싶을 때
- 팀이나 프로젝트별 guardrail을 가볍게 만들고 싶을 때
- Claude의 반복 실수를 대화가 아니라 규칙으로 남기고 싶을 때

## 주의할 점

규칙 파일 위치가 가장 중요합니다. `.claude/hookify.*.local.md` 파일은 현재 프로젝트 루트의 `.claude/`에 있어야 합니다. plugin directory에 만들면 동작하지 않습니다.

pattern은 Python regex syntax를 사용합니다. 너무 넓은 regex는 원치 않는 경고를 많이 만들고, 너무 복잡한 regex는 느려질 수 있습니다. event type을 구체적으로 고르고, pattern은 실제 trigger 예시에서 시작해 조금씩 넓히는 편이 좋습니다.

`block`은 강력합니다. 잘못 설정하면 필요한 작업까지 막을 수 있으므로, 위험도가 명확한 destructive command나 credential 노출 같은 경우에 우선 사용하고, 나머지는 `warn`으로 시작하는 것이 좋습니다.

## 한 문장으로 정리

`hookify`는 Claude에게 반복해서 말하던 "이건 하지 마"를 프로젝트 로컬 hook 규칙으로 바꿔, 다음 tool use부터 경고하거나 차단하게 만드는 플러그인입니다.
