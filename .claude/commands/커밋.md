# 커밋 & 푸시 워크플로우

아래 순서를 반드시 지킨다. 각 단계가 실패하면 즉시 중단한다.

---

## 1단계: 코드 검증

Bash 도구로 다음 두 명령을 **순서대로** 실행한다.

```bash
npx tsc --noEmit
```

```bash
npm run lint
```

**규칙:**
- 둘 중 하나라도 에러(exit code != 0)가 발생하면 **즉시 중단**한다.
- 에러 내용을 사용자에게 명확하게 보고하고, 커밋은 절대 진행하지 않는다.
- 두 명령 모두 통과해야만 2단계로 넘어간다.

---

## 2단계: 변경 내용 파악

다음 명령으로 변경 사항을 파악한다.

```bash
git status
git diff
git diff --staged
```

---

## 3단계: 커밋 메시지 작성

`.claude/rules/git-conventions.md`의 규칙을 따른다.

**형식:** `<타입>. <한글 설명>`

| 타입 | 용도 |
| --- | --- |
| `feat.` | 새 기능 추가 |
| `fix.` | 버그 수정 |
| `refactor.` | 기능 변경 없는 코드 개선 |
| `chore.` | 설정·의존성·빌드 등 비기능 변경 |

**규칙:**
- 설명은 한글로, "무엇을 추가/수정했는가"를 구체적으로 작성한다.
- 논리적 단위가 여러 개라면 가장 대표적인 것으로 하나의 메시지를 작성한다.
- 민감 파일(`.env`, 크리덴셜 등)이 포함되어 있으면 스테이징에서 제외하고 사용자에게 경고한다.

---

## 4단계: 커밋 & 푸시

변경된 파일 목록을 확인한 후, 민감 파일을 제외하고 스테이징한다.

```bash
git add .
git commit -m "<작성한 커밋 메시지>"
git push
```

완료 후 커밋 해시와 푸시된 브랜치를 사용자에게 보고한다.
