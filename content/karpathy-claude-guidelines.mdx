CLAUDE.md를 처음 만들면 자연스럽게 README처럼 작성하게 됩니다. "이 프로젝트는 React를 사용합니다", "src/ 폴더에 컴포넌트가 있습니다" 같은 설명이죠. 하지만 이건 Claude에게 아무런 도움이 안 됩니다. Claude는 코드를 직접 읽으면 알 수 있는 내용은 굳이 CLAUDE.md에서 읽지 않아도 됩니다.

CLAUDE.md가 진짜 효과를 내려면 **가드레일**이어야 합니다. AI가 혼자서는 알 수 없는 숨겨진 규칙, 우선순위, 함정을 담아야 합니다.

---

## CLAUDE.md가 자동으로 로드되는 4가지 위치

CLAUDE.md는 한 곳에만 두는 파일이 아닙니다. 범위에 따라 4가지 위치에 분리할 수 있습니다.

| 위치 | 경로 | 특징 |
| --- | --- | --- |
| 전역 | `~/.claude/CLAUDE.md` | 모든 프로젝트 공통 적용 |
| 팀 공유 | `<repo>/.claude/CLAUDE.md` | 소스 컨트롤에 체크인, 팀 전체 공유 |
| 개인 per-repo | `<repo>/CLAUDE.local.md` | .gitignore 추가, 개인 전용 |
| 서브디렉토리 | `<subdir>/CLAUDE.md` | 특정 폴더 작업 시에만 적용 |

이 구조를 활용하면 "모든 프로젝트 공통 규칙"과 "이 프로젝트만의 규칙"을 분리해서 관리할 수 있습니다.

## 8-layer Context Model: Claude가 참조하는 순서

Claude는 응답을 생성할 때 아래 8개 레이어를 순서대로 쌓아 컨텍스트를 구성합니다.

```
1. 시스템 프롬프트       (Anthropic이 정한 베이스)
2. 도구 정의             (Read, Edit, Bash 등 사용 가능한 도구)
3. 전역 CLAUDE.md        (~/.claude/)
4. 프로젝트 CLAUDE.md    (.claude/)
5. CLAUDE.local.md       (개인 per-repo)
6. 서브디렉토리 CLAUDE.md (특정 폴더 한정)
7. 대화 히스토리         (현재 세션의 이전 메시지)
8. 현재 사용자 메시지    (방금 입력한 한 줄)
```

CLAUDE.md는 3~6번 레이어를 직접 제어할 수 있는 유일한 방법입니다. 위에 있을수록 항상 적용되고, 아래로 갈수록 현재 대화에 가까워집니다.

## Non-obvious Invariants Only: 코드만 봐도 알 수 있는 건 쓰지 마세요

가장 중요한 원칙입니다. CLAUDE.md는 **코드로는 알 수 없는 것**만 담아야 합니다.

### 쓰지 마세요 (코드로 알 수 있는 것)
- "이 프로젝트는 React를 사용합니다"
- "src/ 폴더에 컴포넌트가 있습니다"
- "TypeScript로 작성됐습니다"
- "테스트 폴더는 `__test__/` 입니다"

### 써야 합니다 (숨은 규칙, gotcha)
- "Hooks 안에서 fetch 직접 호출 금지 — useSWR 써야 함"
- "auth/ 폴더 수정할 땐 보안팀 리뷰 필수"
- "any 타입은 PR 자동 거절"
- "테스트는 실제 DB 사용 — mock 금지"

Claude가 코드를 읽어서 알 수 있는 내용은 CLAUDE.md에 쓸수록 토큰 낭비입니다. 코드가 말해주지 않는 **의사결정 기준**이 CLAUDE.md의 자리입니다.

## 공식 4가지 작성 원칙 (Anthropic 권장)

Anthropic이 공식으로 권장하는 CLAUDE.md 작성 원칙입니다. **1번이 제일 중요**합니다.

1. **구체적으로** — "잘 짜라" X → "함수 30줄 넘으면 분리, any 금지" O
2. **구조화된 마크다운** — 섹션과 목록으로 읽기 쉽게
3. **정기 검토** — 한 달에 한 번 안 쓰는 규칙 잘라내기
4. **간결하게** — 100줄 이하 유지 (always-on 비용)

## High-ROI 실수 → 반영 사이클

CLAUDE.md를 처음부터 완벽하게 쓰려 하지 마세요. **Claude가 실수할 때마다 그 자리에서 바로 반영**하는 게 가장 효율적입니다.

> **Claude가 실수했을 때 즉시:** "이 실수는 다시는 안하게 CLAUDE.md에 반영해줘"

```
1. Claude가 실수
2. 즉시 반영 요청
3. 규칙 한 줄 추가
4. 영구적 해결
```

이 사이클이 돌기 시작하면 CLAUDE.md는 자동으로 자랍니다. 억지로 채울 필요가 없습니다.

## build · test 명령어 명시 + @import로 분할 관리

한 블록만 추가해도 결과 품질이 2~3배 올라가는 항목입니다.

### 빌드 · 테스트 명령어 명시

Claude가 명령어를 추측하지 않게 합니다. package.json을 뒤져보고 실패하는 시간 = 토큰 낭비입니다.

```markdown
## 명령어
- 빌드: `npm run build`
- 테스트: `npm test -- --run` (watch 모드 금지)
- 린트: `npm run lint:fix`
- 타입체크: `tsc --noEmit`
```

명시되어 있으면 바로 정답으로 갑니다. 없으면 추측 → 시도 → 실패 → 재시도 루프입니다.

### @import로 모듈 분리

CLAUDE.md가 80~100줄에 가까워지면 주제별로 쪼개세요. 자동으로 합쳐져 로드됩니다.

```markdown
# CLAUDE.md
@./docs/coding-style.md
@./docs/testing-rules.md
@./docs/security.md
```

**보너스:** 같은 파일을 `AGENTS.md`로 저장하면 OpenAI Codex도 같은 파일을 읽습니다. 한 파일 = 두 도구.
