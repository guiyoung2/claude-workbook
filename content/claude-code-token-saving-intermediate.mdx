초급 팁을 모두 적용하고 있는데도 토큰이 빠르게 소진된다면? 이 글은 설정 파일과 도구 관리 레벨에서 토큰을 구조적으로 줄이는 방법을 다룹니다. 세션당 최대 15,000 토큰을 절약할 수 있는 중급 전략들입니다.

## 프로젝트 설정: 한 번만 해두면 계속 효과

### 1. .claudeignore 파일 만들기

클로드는 탐색할 때 `node_modules`, `.next`, `dist` 같은 폴더까지 전부 읽으려 합니다. 큰 프로젝트라면 토큰이 순식간에 녹아버립니다.

`.gitignore`처럼 클로드가 읽지 않을 파일과 폴더를 지정할 수 있습니다.

```
# .claudeignore 예시
node_modules/
.next/
dist/
build/
*.log
coverage/
```

**팁:** "이 프로젝트 `.claudeignore` 추천해줘"라고 하면 프로젝트 기반으로 잘 만들어줍니다. 프로젝트 초반에 한 번만 만들어두면 계속 유효합니다.

### 2. CLAUDE.md는 200줄 이하로 유지하기

CLAUDE.md는 세션 시작 때만 읽히는 게 아닙니다. **매 메시지마다 읽힙니다.** 200줄짜리 CLAUDE.md는 메시지 한 번에 200줄씩 계속 쌓이는 겁니다.

다이어트 방법:

- "이 프로젝트는…" 같은 서술형 문장 제거
- 헤딩·리스트·테이블로 구조화
- 규칙은 최소 단위로 축약, 코드 예시 남발 금지
- 200줄을 넘기 시작하면 파일 분리 타이밍

### 3. 상세 지식은 스킬 파일로 분리하기

CLAUDE.md를 200줄 이하로 유지하면서 나머지 내용은 어디에? **스킬 파일로 분리**하세요.

```
# 항상 로드
CLAUDE.md             ← 핵심 규칙만 (200줄 이하)

# 필요할 때만 로드
docs/api-guide.md
docs/db-guide.md
docs/deploy-guide.md
```

CLAUDE.md에 이렇게 명시해두면 됩니다:

```
API 관련 작업이 필요하면 docs/api-guide.md를 읽어라.
```

스킬 파일은 필요할 때만 메모리에 로드되므로 **세션당 최대 15,000 토큰을 절약**할 수 있습니다.

### 4. CLAUDE.md에 5가지 절약 규칙 추가하기

직접 넣어두면 클로드가 스스로 낭비를 줄입니다:

```markdown
## 토큰 절약 규칙
- 이미 읽은 파일은 다시 확인하지 않는다
- 불필요한 도구 호출은 하지 않는다
- 가능한 도구 호출은 동시에 실행한다
- 20줄 이상의 불필요한 출력은 서브에이전트에 위임한다
- 사용자가 이미 설명한 내용을 다시 반복하지 않는다
```

특히 1번(파일 재확인 금지)과 5번(반복 요약 금지)이 효과가 큽니다.

### 5. CLAUDE.md에 이미 결정된 내용 적어두기

한 번 저장해두면 다시는 프롬프트로 타이핑하지 않아도 됩니다:

- 안정적인 아키텍처 결정 (이미 정해진 방향)
- 코딩 규칙과 컨벤션 (매번 설명할 필요 없음)
- 빌드·테스트·배포 명령어 (자주 묻는 것들)
- 자주 하는 실수와 해결책 (반복 실수 방지)

**단,** 자동 학습 설정 시 파일이 너무 길어지지 않는지 주기적으로 확인하세요.

## 파일 참조와 컨텍스트 관리

### 6. @로 파일 전체 참조 지양하기

`@` 기호로 파일을 참조하면 해당 파일 내용 전체가 컨텍스트에 포함됩니다.

| 파일 크기 | 권장 방법 |
| --- | --- |
| 500줄 이하 | 전체 참조 가능 |
| 500 ~ 2,000줄 | 필요한 구간만 지정 |
| 2,000줄 이상 | 함수·클래스 단위로 분리해서 참조 |

### 7. 60% 시점에 수동으로 압축하기

클로드는 컨텍스트가 95% 차면 자동으로 압축합니다. 하지만 그때는 이미 컨텍스트 품질이 상당히 저하된 상태입니다.

**권장 방법:**

1. `/context`로 사용률 확인
2. 60% 도달 시 수동으로 `/compact` 실행
3. 보존할 내용을 함께 지시하기:

```
/compact 실행해줘.
현재 구현 중인 로그인 기능의 핵심 로직과 발생한 에러 내역은 반드시 보존해줘.
```

압축을 3~4번 해야 할 정도로 길어지면 세션 요약 후 `/clear`하고 새로 시작하세요.

### 8. 자리 비우기 전에 압축하거나 클리어 하기

프롬프트 캐시 만료 시간은 **5분**입니다. 5분 후 돌아오면 처음부터 재처리됩니다. 갑자기 사용량이 확 오르는 느낌이 바로 캐시 만료 때문입니다.

자리를 비울 거라면 반드시 `/compact`나 `/clear` 먼저.

### 9. 셸 명령어의 긴 출력 주의하기

클로드가 셸 명령어를 실행하면 전체 출력이 컨텍스트로 그대로 들어옵니다.

**위험한 패턴:**

- 커밋 200개짜리 `git log`
- verbose 옵션 켠 전체 테스트 결과
- 빌드 경고 메시지 가득한 로그

**대응 방법:**

- "전체 테스트" → "auth 모듈 테스트만"
- 훅으로 출력을 `head`/`tail`로 자동 상한선 설정
- 필요 없는 명령어는 해당 프로젝트에서 권한 거부

### 10. 대규모 작업 후 그냥 /clear 하지 않기

컨텍스트가 너무 커지면, 날리기 전에 저장하고 이어받기를 하세요:

```
# 1단계: 진행 상황 저장
"지금까지 진행한 내용을 progress.md로 정리해줘.
완료된 것, 진행 중, 다음 단계 포함해서"

# 2단계: 컨텍스트 초기화
/clear

# 3단계: 이어서 작업
"@progress.md 읽고 이어서 작업 계속해줘"
```

## MCP 서버 관리: 연결할수록 비용이 오른다

### 11. MCP 서버는 최소화하기

MCP 서버를 연결하면 매 메시지마다 해당 서버의 모든 도구 정의가 컨텍스트에 로드됩니다. **아무 말 안 하고 엔터만 쳐도 토큰이 소모됩니다.** `/mcp`로 현재 연결된 서버를 바로 확인해보세요.

안 쓰는 서버 3개만 끊어도 체감이 확 달라집니다.

### 12. 4단계로 MCP 서버 줄이기

1. **전체 목록화** — `~/.claude/settings.json`의 `mcpServers` 키 확인 후 전부 나열
2. **도구 수 확인** — 각 서버에 어떤 도구가 있는지, 설명이 얼마나 장황한지 체크
3. **토큰 비용 추정** — `예상 토큰 = (도구 수 × 200) + (설명 글자 수 ÷ 4)`
4. **상위 오버헤드 서버 제거** — 비용 내림차순 정렬 시 2~3개가 전체 대부분. 그것부터 정리

### 13. 글로벌 vs 프로젝트 레벨 MCP 분리하기

모든 MCP를 글로벌에 넣으면 가벼운 프로젝트에서도 전부 로드됩니다.

| 레벨 | 넣어야 할 것 |
| --- | --- |
| 글로벌 | 모든 프로젝트에서 항상 쓰는 것만 |
| 프로젝트 | 해당 프로젝트에만 필요한 것 |

## 고급 전략

### 14. 플랜 모드 먼저 활용하기

토큰 낭비의 최대 원인은 잘못된 방향으로 코드를 잔뜩 작성하고 전부 버리는 상황입니다.

- **Shift + Tab 2번**으로 플랜 모드 진입
- 클로드가 어떤 파일을 수정할지, 어떤 순서로 할지, 리스크는 뭔지 아웃라인 작성
- 확인하고 승인하면 그때 실행으로 넘어감

CLAUDE.md에 추가하면 더 효과적입니다:

```
95% 확신이 생기기 전에는 어떤 변경도 하지 말아줘.
그 확신에 도달할 때까지 추가 질문을 해줘.
```

### 15. 서브에이전트 비용 제대로 인식하기

에이전트 워크플로우는 단일 세션 대비 **최대 10배 더 토큰을 사용**합니다. 각 서브에이전트가 깨어날 때마다 자신만의 전체 컨텍스트를 다시 로드하기 때문입니다.

**현명하게 쓰는 방법:**

- 단발성 작업에만 활용
- 탐색·리서치 작업 위임
- 20줄 이상의 분석 작업

**모델 선택 팁:** 서브에이전트에는 Haiku를 활용하세요. Sonnet/Opus보다 훨씬 저렴합니다.

### 16. 반복 문서는 Projects에 업로드하기

같은 PDF나 문서를 여러 채팅에서 반복 업로드하면 매번 토큰으로 변환됩니다.

```
❌ 반복 업로드: 10번 업로드 = 10번 토큰 소모
✅ Projects 활용: 한 번 업로드 → 캐시 참조 → 추가 토큰 없음
```

claude.ai의 Projects 기능을 반드시 활용하세요.

## 토큰 사용량 확인하는 3가지 방법

```bash
/context                    # 컴포넌트별 토큰 사용량 (60% 압축 기준점 확인)
~/.claude/projects/         # 로그 파일 직접 확인 (JSONL 형식)
```

**웹 토큰 계산기:**

- token-counter.app/anthropic
- claude-tokenizer.vercel.app

CLAUDE.md가 실제로 몇 토큰인지 확인해보세요. 생각보다 클 수 있습니다.

**Status Line 설정:** 터미널에서 `/statusline` 입력 후 설정 적용. 압축 타이밍을 잡기 훨씬 쉬워집니다.

## 마무리

3. MCP 서버 정리
