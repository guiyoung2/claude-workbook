클로드 코드를 열자마자 바로 작업을 시작하시나요? 잠깐만요. 습관 하나가 토큰 수십 개를 아끼기도, 낭비하기도 합니다. 이 글에서는 별도 설정 없이 지금 당장 적용할 수 있는 초급 토큰 절약 전략을 정리했습니다.

---

## 세션 관리: 맥락을 깔끔하게

### 새 작업 전에 반드시 /clear

클로드는 매 응답마다 지금까지의 대화 전체를 다시 읽습니다. 이전 작업의 컨텍스트가 남아 있으면 그게 모두 토큰입니다. **새 작업이 시작될 때마다 `/clear`로 초기화하세요.**

### 1세션 = 1작업 원칙

버그 3개 고치면서 기능 2개 추가하고 리팩토링까지 한 세션에 몰아서 하려고 하면?

- 컨텍스트가 오염돼 클로드가 이전 작업 내용을 계속 돌고 다님
- 심하면 할루시네이션 발생

**한 세션에는 하나의 논리적 작업만.** 끝나면 `/clear`하고 다음 작업 시작.

### 세션 시작 전에 작업 목록 미리 정리하기

클로드 코드를 열기 전에 딱 3가지만 해두세요:

- 오늘 처리할 작업 목록 작성
- 우선순위 정해서 가장 중요한 것부터
- 5시간 세션을 하나의 스프린트처럼 대하기

목표가 명확하면 불필요한 탐색 토큰을 아낄 수 있습니다.

---

## 프롬프트 작성: 범위를 좁혀라

### 구체적인 프롬프트 보내기

```
❌  "이 코드 개선해줘"
✅  "user.js의 verifyUser 함수에 입력값 검증 추가해줘"
```

파일명, 함수명, 조건을 명시적으로 주세요. 클로드가 알아서 탐색하게 두면 그 탐색 비용이 전부 토큰입니다.

### 간단한 명령은 한 번에 묶어서 보내기

```
❌  "요약해줘" → "포인트 뽑아줘" → "제목 추천해줘"   (3번 = 3배 과금)
✅  "요약하고, 핵심 포인트 뽑고, 제목도 추천해줘"    (1번 = 1배 과금)
```

한 번에 묶으면 응답 품질도 올라갑니다.

### 틀린 답변은 후속 메시지 대신 원본 편집

클로드가 잘못 답했을 때 "아니 그게 아니라…"라고 후속 메시지를 보내면 잘못된 응답이 컨텍스트에 그대로 남습니다. 대신 **원본 메시지의 편집 버튼으로 수정하고 재생성**하세요. 잘못된 기록이 컨텍스트에서 사라집니다.

### 붙여넣기는 꼭 필요한 것만

파일이나 문서를 통째로 붙여넣기 전에 한 번만 생각해보세요:

| 상황 | 붙여넣을 것 |
| --- | --- |
| 버그가 함수 하나에 있다면 | 그 함수만 |
| 단락 하나의 맥락만 필요하다면 | 그 단락만 |
| 파일 전체를 던지면 | 전체가 다 토큰 |

## 작업 중 모니터링: 자리 지키기

Shift + Tab 자동 수락 모드로 켜놓고 자리 비우는 분들 많은데, 생각보다 위험합니다:

- 클로드가 잘못된 방향으로 달려가는 경우 많음
- 같은 파일을 반복해서 읽는 루프에 빠지는 경우도 있음
- **초반에 발견해서 멈추면 수천 개의 토큰을 아낄 수 있음**

작업 초반만이라도 옆에서 지켜보면서 의도치 않은 루프를 확인하세요.

## 모델 선택: 도구에 맞는 모델을

### 기본 모델을 Sonnet으로 고정

처음 켰을 때 기본 모델이 Opus로 잡혀 있는 경우가 있습니다. Opus는 Sonnet보다 **4~5배 더 비쌉니다.** 설정 파일에 한 줄만 추가해서 Sonnet으로 고정하세요.

### 작업에 맞는 모델 선택하기

| 모델 | 비유 | 적합한 작업 | 비용 |
| --- | --- | --- | --- |
| Haiku | 주니어 개발자 | 학습, 단순 질문, 간단한 실습 | 가장 저렴 |
| Sonnet | 중급 개발자 | 일반 코딩, 기능 구현, 파일 수정 | **기본값 권장** |
| Opus | 시니어 개발자 | 복잡한 아키텍처 설계, 깊은 디버깅 | Sonnet의 4~5배 |

## 기능 설정: 안 쓰는 건 끄기

### Extended Thinking 필요할 때만 켜기

Extended Thinking(확장된 사고) 기능이 활성화되어 있으면, 단순한 파일 수정 하나에도 **최대 3만 토큰**을 출력 토큰으로 소모할 수 있습니다. 복잡한 설계나 깊은 디버깅이 아닌 이상 꺼두세요.

웹 검색, 커넥터 같은 기능도 켜져 있기만 해도 매 응답마다 추가 토큰이 소모됩니다.

### Memory와 User Settings에 역할 저장

매 채팅마다 이런 걸 타이핑하시나요?

```
"나는 프론트엔드 개발자야. 리액트와 넥스트.js 위주로 설명해줘. 코드는 간결하게 작성해줘"
```

이게 메시지당 3~5개 토큰을 잡아먹습니다. **Settings → Memory and User Settings에 역할과 스타일을 한 번만 저장**하면 모든 새 채팅에 자동으로 적용됩니다.

## 시간대와 리셋 전략

### 롤링 윈도우를 이해하고 세션 나누기

클로드 코드는 자정에 리셋되지 않습니다. **최근 5시간 동안 사용한 양만 한도에 포함되는 롤링 윈도우 방식**입니다.

| 세션 | 전략 |
| --- | --- |
| 오전 | 핵심 작업 집중, 한도 전부 써도 OK |
| 오후 | 오전 사용량이 윈도우에서 빠짐 → 새 한도로 재시작 |
| 저녁 | 오후 사용량도 만료 → 체감 한도 훨씬 넉넉 |

### 리셋 타이밍 전략적으로 활용하기

- **리셋이 곧 다가오는데 할당량이 많이 남아 있다면?** → 과감하게 써버리세요. 어차피 리셋되면 초기화됩니다.
- **할당량이 얼마 안 남았는데 리셋까지 시간이 많이 남았다면?** → 잠깐 쉬세요. 풀 예산으로 다시 시작하는 게 낫습니다.

### 피크 타임 피하기

| 피크 시간대 | 한국 시간 |
| --- | --- |
| 미국 동부 오전 8시 ~ 오후 2시 | 밤 10시 ~ 새벽 4시 |

한국 업무 시간(9시~6시)은 미국 비피크 시간대입니다. 평소대로 낮에 작업하면 됩니다.

## 유용한 명령어 모음

```bash
/clear           # 컨텍스트 초기화
/rename          # 현재 세션 이름 지정 (나중에 /resume으로 복귀 가능)
/resume          # 이름 붙인 이전 세션으로 돌아가기
/context (/ctx)  # 컴포넌트별 토큰 사용량 확인
/cost (/cst)     # 현재 세션 실제 토큰 사용량 → 예상 비용
/usage (/use)    # 현재 세션 + 주간 사용량 한눈에 확인
```

**사용량 모니터링 팁:** 클로드 계정 대시보드를 작업하는 동안 옆 탭에 열어두고 30~40분마다 확인하세요. 또는 `npm install -g @ryoppippi/ccusage`로 CLI에서 일별·월별·실시간 사용량을 확인할 수 있습니다.

## 실전 체크리스트

- [ ] 기본 모델이 Sonnet으로 설정되어 있는지 확인
- [ ] Extended Thinking 기능이 불필요하게 켜져 있지 않은지 확인
- [ ] Memory and User Settings에 역할·스타일 저장 완료
- [ ] 새 작업 시작 전 `/clear` 습관화
- [ ] 프롬프트에 파일명·함수명·조건을 명시적으로 포함
- [ ] 여러 간단한 질문은 한 번에 묶어서 보내기
- [ ] 작업 초반에는 클로드 옆에서 모니터링하기
- [ ] 사용량 대시보드를 옆 탭에 열어두고 30~40분마다 확인

## 마무리

토큰을 아끼는 건 비용 절감 그 이상입니다. 컨텍스트가 깔끔할수록 클로드의 응답 품질도 올라갑니다.

**모델 고정 + `/clear` 습관화 + 구체적인 프롬프트.** 이것만으로도 체감 차이가 납니다.
